# Как работает оплата и как её настроить

## Схема

1. Пользователь выбирает пакет → фронтенд отправляет на сервер только `packageId`.
2. Сервер создаёт заказ и возвращает **уникальную сумму**: цена пакета минус случайная скидка 1–99 сум
   (например, 7 990 → 7 951). Заказ действует 15 минут (`ORDER_TTL_SECONDS`).
3. Пользователь переводит **ровно эту сумму** на карту (Click / Payme).
4. На телефон владельца карты приходит SMS → приложение-пересыльщик отправляет его на
   `POST /api/webhook/sms`.
5. Сервер находит активный заказ с точно такой суммой (если точной нет, подходит единственный заказ
   в пределах ±100 сум), помечает его оплаченным и начисляет монеты одной транзакцией. Фронтенд раз в 3 секунды опрашивает статус заказа и показывает «Оплата прошла».

Скидка нужна, чтобы по сумме можно было однозначно понять, кто платит. Если бы у двух людей была
одинаковая сумма, платёж одного мог бы зачесться другому.

## Переменные окружения

См. `.env.example`. Обязательные:

- `JWT_SECRET`: длинная случайная строка (подпись токенов входа).
- `SMS_WEBHOOK_SECRET`: секрет вебхука SMS. **Пока он не задан, автоматическое зачисление отключено (503).**

## Настройка пересылки SMS

В приложении, которое пересылает SMS с телефона на сервер (SMS Forwarder и подобные), настройте HTTP-запрос:

- Метод: `POST`
- Адрес: `https://<ваш-сервер>/api/webhook/sms`
- Заголовок: `x-webhook-secret: <значение SMS_WEBHOOK_SECRET>`
  (если приложение не умеет заголовки, можно добавить в адрес: `.../api/webhook/sms?secret=<значение>`)
- Тело (JSON): `{"text": "<текст SMS>"}`.

Пересылайте только SMS о поступлениях на карту. SMS без суммы сервер просто игнорирует.

## Разбор проблем

**Человек заплатил, а монет нет.** Все входящие SMS с распознанной суммой записываются в таблицу
`sms_log` (текст, сумма, id заказа или пусто, если подходящего заказа не нашлось):

```sql
SELECT * FROM sms_log ORDER BY id DESC LIMIT 20;
```

Типичные причины: человек заплатил не ту сумму, заказ уже истёк (15 минут),
SMS не дошёл до сервера, неверный `SMS_WEBHOOK_SECRET`. В таких случаях монеты можно начислить вручную.

**Порядок выкладки.** Backend и frontend надо выкладывать вместе: старый фронтенд не передаёт токен,
а новый backend без токена платёжные запросы отклоняет (401).

Тесты поднимают настоящий сервер на временной базе и проходят весь сценарий: заказ → SMS → зачисление,
